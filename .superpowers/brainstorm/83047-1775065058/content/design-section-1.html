Design — Section 1: Map Overlays

New hooks added to lib/map/ following existing patterns

useMapHeatmap

Adds a MapLibre heatmap layer using red-force asset positions. Derived purely from the assets prop — no new data model. Registered as a togglable layer in the existing MapLayerContext ("Threat Heatmap"). The hook watches for style changes (same pattern as useMapSensorCircles) and redraws on every sim tick.

Heatmap layer config
type: "heatmap"
source: red-force positions
weight: health_pct (0–1)
radius: 40px
intensity: asset density
color: green → yellow → red
red-force density preview

useMapZoneControl

Computes per-tick Voronoi regions from all alive asset positions (blue + red), then renders filled GeoJSON polygons clipped to the map bounds. Blue zones: rgba(74,144,226,0.12), Red zones: rgba(224,92,92,0.12). Contested cells (assets of both factions within 30km) rendered in amber. Recomputed client-side using a lightweight Voronoi library — no server round-trip.

Mini-Map (Pop-out Panel)

A "MINIMAP" button added to the map toolbar. Click opens a floating MapViewInner instance at 260×180px, positioned top-right, showing all assets at reduced scale. Non-interactive (no click/context menu). Shares the same assets and visibleLayers props as the main map. Closes on button re-click or ESC. Implemented as a React component, not a new hook — it's a second map instance, not a MapLibre layer.

Event Timeline Drawer

A collapsible drawer attached to the bottom of the map viewport. A thin handle bar is always visible (showing event count badge). Click expands to ~200px showing a chronological list of sim events: strikes launched, assets destroyed, missions aborted, counterattacks triggered. Events sourced from the existing strikeLog and sim state in use-simulation.ts. No new server data needed. Each entry clickable to pan/select the relevant asset on the map.
