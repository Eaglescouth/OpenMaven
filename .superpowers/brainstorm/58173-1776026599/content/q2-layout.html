Feature C — SIGINT / Comms Intelligence Feed

Question 2 of 4: Where does the SIGINT UI live?

A

New dedicated page — /sigint

A full tab in the nav (like Overview and Map). Left panel: live intercept feed. Right panel: map with pulse rings showing intercept locations. Same pattern as the Overview page — useSimulation() called fresh, SimulationControls at the top.

Pros

  • Full screen real estate for the feed
  • Follows the established page pattern exactly
  • Map rings visible without leaving SIGINT view

Cons

  • Another WebSocket connection (one per page)
  • Can't see SIGINT rings on the main map page
B

Drawer / panel on the existing Map page

A collapsible side panel on /map (like the Event Timeline Drawer already there). SIGINT feed slides in from the right. Pulse rings always render on the main tactical map.

Pros

  • Pulse rings visible alongside tactical picture
  • Single WebSocket connection
  • Follows the drawer pattern (EventTimelineDrawer)

Cons

  • Map page is already crowded
  • Less room for intercept feed details
C

Split — dedicated page plus pulse rings on Map

A new /sigint tab for the full feed. Pulse rings also render on /map (toggled like sensor ranges). SIGINT data lives in a shared context so both pages consume it without duplicate WebSocket connections.

Pros

  • Best of both — full feed page + tactical map integration
  • Single shared data source via context

Cons

  • Most work — new context, new page, new map hook
  • Context adds complexity to app shell
